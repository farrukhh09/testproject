# Meridian CRM — маркетинговые рассылки в Telegram и WhatsApp

Локальная CRM для рассылок существующим клиентам, которые дали согласие на рекламу.

**Сейчас это прототип интерфейса.** Это один HTML-файл с вымышленными данными. Сеть он не использует, сообщения никуда не отправляет.

## Как открыть

Двойной щелчок по `prototype/crm_prototype.html`. Ничего устанавливать не нужно.

Шрифты загружаются из Google Fonts. Если интернета нет, браузер подставит системные шрифты, и всё продолжит работать.

## Принятые решения

- **Telegram — два режима.**
  - **Бот** пишет только тем, кто сам нажал «Start» по личной ссылке или QR-коду.
  - **Ручная очередь**: оператор отправляет со своего аккаунта, а CRM готовит текст, ведёт учёт и держит дневной лимит (по умолчанию 40).
  - Автоматическую рассылку с личного аккаунта не делаем. Это нарушает правила Telegram, и аккаунт быстро блокируют.
- **WhatsApp — только официальный Cloud API** и только одобренные шаблоны категории «Маркетинг».
  - Проверить заранее, есть ли у номера WhatsApp, нельзя. Статус «неизвестно» сохраняется до первой отправки.
- **Согласие хранится отдельно по каждому каналу.** Без доказательства согласия клиент получает статус «неизвестно», и писать ему нельзя.
- **Отписка всегда сильнее.** Повторный импорт Excel её не снимает. Снять отписку можно только новым согласием с доказательством.
- **Перед каждым сообщением согласие проверяется ещё раз.** Одному клиенту в рамках одной кампании сообщение уходит не больше одного раза.
- **Если ответ API потерялся, повтора нет.** Статус уточняется через webhook. Повторяются только временные ошибки, например «слишком много запросов».

## Ограничения платформ, которые видны в интерфейсе

- Telegram не сообщает о доставке и прочтении сообщений бота. В отчёте будет только «принято» или ошибка, например «клиент заблокировал бота».
- WhatsApp присылает статусы «отправлено», «доставлено», «прочитано» и «ошибка» позже, через webhook. Для webhook нужен публичный https-адрес.
- Meta может сама не доставить рекламное сообщение (ошибка 131049). Повторять отправку в этом случае нельзя.

## Проверка одного номера (для теста)

Раздел «Каналы» → карточка «Проверка номера». Вводите номер, нажимаете «Проверить» и получаете ответ по двум мессенджерам.

- **Telegram** проверяется автоматически, через ваш аккаунт: официальный метод поиска по номеру `contacts.resolvePhone`. Номер в контакты не добавляется. Ответ бывает трёх видов:
  - «есть»;
  - «не найден» — аккаунта нет или человек скрыл номер в настройках приватности, различить нельзя;
  - «лимит Telegram, подождите».
- **WhatsApp** автоматически проверить нельзя: в официальном API такой проверки нет. Кнопка «Открыть в WhatsApp» открывает чат по ссылке `wa.me`. Если открылся чат — WhatsApp есть. Если WhatsApp пишет «номер не зарегистрирован» — нет. Результат вы отмечаете сами.

Проверка работает, только когда страница открыта через проверщик. Если открыть HTML-файл двойным щелчком, карточка покажет «Проверщик не запущен».

### Первый запуск

1. **Получите ключи.** Откройте https://my.telegram.org, войдите и выберите «API development tools». Создайте приложение с любым названием и запишите `api_id` и `api_hash`.
2. **Впишите ключи.** В папке `checker` скопируйте `.env.example` в `.env` и впишите в него оба значения.
3. **Запустите проверщик одной командой:** в папке `MARKETING_CRM` дважды щёлкните `start_checker.cmd`.
   - **Первый раз** в окне появится QR-код. На телефоне откройте Telegram → Настройки → Устройства → «Подключить устройство» и наведите камеру на код. Коды подтверждения не запрашиваются, поэтому ответа «слишком много попыток» не будет. Если включён пароль двухэтапной проверки, окно попросит его, ввод скрыт. Если камера не читает код с экрана, откройте картинку, путь к ней написан под кодом.
   - **В следующие разы** QR-кода не будет: вход сохранён.
   - Ключи от my.telegram.org могут быть с другого аккаунта: входить можно любым. Тот аккаунт не удаляйте, ключи привязаны к нему.

   После входа браузер сам откроет страницу по ссылке-входу. Ссылка видна и в окне проверщика: она меняется при каждом запуске, никому её не пересылайте. Ключ хранится только в этой вкладке и переживает её перезагрузку. Если вкладку закрыли или проверщик перезапустили, снова откройте ссылку из его окна. Если порт 8765 занят другой программой (например, SSH-туннелем), проверщик сам возьмёт следующий свободный и напишет в окне, какой. Остановить проверщик — Ctrl+C в его окне.

### Запуск на Mac

1. **Перенесите папку** `MARKETING_CRM` на Mac без подпапки `.venv`. Файл `checker/.env` с ключами не пересылайте через мессенджеры и почту. Скопируйте его флешкой или создайте заново из `checker/.env.example`.
2. **Нужен Python 3.12 или новее.** Проверить: `python3 --version` в Terminal. Поставить: установщик с https://www.python.org/downloads/macos/ или `brew install python@3.12`.
3. **Первая настройка, один раз.** В Terminal наберите `cd ` (с пробелом), перетащите папку `MARKETING_CRM` в окно Terminal и нажмите Enter. Затем:
   ```
   bash setup_mac.command
   ```
   Скрипт:
   - создаст окружение `.venv`;
   - поставит пакеты из `requirements.txt`;
   - разрешит запуск `start_checker.command` и `telegram_logout.command` двойным щелчком.
4. **Запуск.** Дважды щёлкните `start_checker.command`. Если macOS пишет, что файл от неизвестного разработчика: правый щелчок → «Открыть» → «Открыть».
   - **Первый раз** появится QR-код, как на Windows. Он рисуется чёрным по белому и читается при любой теме Terminal.
   - **Если камера его не видит,** откройте картинку: `open ~/Library/Application\ Support/MeridianChecker/state/login_qr.png`.
5. **Выход из Telegram:** дважды щёлкните `telegram_logout.command`.

Сессия и лимит лежат в `~/Library/Application Support/MeridianChecker`, доступ к папке есть только у вашей учётной записи Mac.

### Если серверы Telegram недоступны

Окно пишет «Серверы Telegram недоступны из этой сети», хотя web.telegram.org в браузере работает.

- **Почему.** Веб-версия ходит в Telegram как обычный сайт. Программы — Telegram Desktop, наш проверщик — подключаются к серверам Telegram напрямую, по их адресам.
- **Что закрыто.** В одной корпоративной сети были закрыты 149.154.167.51, 95.161.76.100, 149.154.175.100, 149.154.167.91 и 91.108.56.130, а открыты только 149.154.175.53 и 149.154.167.50. Порты 443, 80 и 5222 дают одинаковый результат. Похоже на намеренную блокировку.
- **Варианты:**
  1. Попросить ИТ или службу безопасности разрешить этому компьютеру доступ к серверам Telegram.
  2. Запустить проверщик на компьютере вне корпоративной сети. Скопируйте папку `MARKETING_CRM` без `.venv`, поставьте Python 3.12 или новее и выполните в этой папке:
     ```
     python -m venv .venv
     .venv\Scripts\python -m pip install telethon phonenumbers python-dotenv segno
     ```
     Затем запустите `start_checker.cmd`.
- **Не делайте:** обходить блокировку на рабочем компьютере через VPN, прокси или запасные адреса без разрешения ИТ.

### Защита

- **Файл сессии** лежит не в папке проекта, а в `%LOCALAPPDATA%\MeridianChecker\session`. Доступ к этой папке есть только у вашей учётной записи Windows. Файл даёт полный доступ к аккаунту Telegram, поэтому не копируйте его никуда.
- **Удаление файла доступ не отзывает:** его копия продолжит работать. Отозвать доступ можно двумя способами:
  - `telegram_logout.cmd` — Telegram закроет сеанс, и файл станет бесполезным;
  - Telegram → Настройки → Устройства → завершить сеанс.
- **Только вы и только с этого компьютера.** Проверщик отвечает только на адрес 127.0.0.1. Ключ страница получает только после входа по ссылке из окна проверщика. Запросы с других сайтов и от других пользователей компьютера отклоняются.
- **Один экземпляр.** Второй проверщик или вход в Telegram, пока первый работает, не запустятся: они делят один файл сессии.
- **Лимиты** (меняются в `.env`):
  - не больше 20 проверок в час (максимум 60) и 50 в сутки (максимум 200);
  - пауза 5 секунд между проверками;
  - если Telegram просит подождать, проверки приостанавливаются на это время, в том числе после перезапуска. Повторов во время ожидания нет: именно они ведут к ограничению аккаунта.
  - Если Telegram вернул незнакомую ошибку, проверки приостанавливаются на час.
- **Полных номеров нет нигде:** в журнал и в список на странице попадает только маска (+992•••••••56). Данные найденных людей в файле сессии не сохраняются.
- **WhatsApp:** кнопка «Открыть в приложении» запускает WhatsApp на компьютере. Кнопка «Через сайт» оставит номер в истории браузера и передаст его сайту WhatsApp.
- **Python проекта** — своё окружение `MARKETING_CRM\.venv` (Python 3.14, пакеты telethon, phonenumbers, python-dotenv). Файлы `.cmd` запускают программы через него. Обычный `python` в консоли этих пакетов не видит.
- **Тесты** работают без сети: в папке `checker` выполните `..\.venv\Scripts\python -m unittest discover -s tests`.

Рабочая версия: Python + FastAPI + SQLite на этом компьютере, а этот интерфейс станет её основой. Node.js не нужен.

1. Импорт настоящего Excel (pandas, openpyxl, phonenumbers), модели базы, тесты.

5. Кампании и экран подтверждения на настоящих данных.
6. Тесты на вымышленных номерах, проверка безопасности, инструкция по настройке API.
